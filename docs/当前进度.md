# 当前进度

## 1. 当前阶段

已接通 Submit → Start → Claim → Handler → 真实结果上报，以及独立的 Renew 和 Reclaim 循环。到期租约按尝试预算回收，到期重试重新入队并经过正常 Claim。取消、查询和完整退出仍待实施。

## 2. 已完成的工作

### 2.1 设计与文档

七个核心操作契约、任务字段说明和执行权、租约、重试、取消等机制已建立。设计入口见[项目概览](项目概览.md)，Submit 的接口与存储边界见已接受的 [ADR-0001](adr/0001-submit-client-and-storage.md)；文档已确定不代表对应流程已实现。

### 2.2 Server 本地基础组件

- **构造、注册与启动前检查**：完成配置校验、执行槽和本地表初始化、Handler 注册及启动时封存注册、生成实例身份。构造不请求 Redis 或启动 goroutine；最小启动接入见第 2.6 节，完整生命周期尚未实现。
- **本地执行记录**：业务任务与执行身份分离，按任务 ID 和执行令牌保存续租资格；记录不证明租约有效或续租正在运行，快照和取消不持锁等待网络或回调。
- **结果设置**：完成 JSON 编码、独立缓冲区和大小限制，失败时保留已有结果；成功结果由 complete 保存，未设置结果与 JSON null 的语义见其契约。

实现与测试见 [server.go](../server.go)、[server_test.go](../server_test.go)。

### 2.3 Client Submit

- 完成提交入口、选项与参数校验，通过嵌入 Lua 原子创建任务详情并入队；同 ID、同初始配置确认已有任务，不同配置返回冲突，缺失配置作为存储异常处理。重复提交不重置运行状态或重新入队。
- 校验脚本响应并保留底层错误链；Redis 连接由调用方配置和关闭，平台不增加 Submit 重试循环或修改共享客户端配置。

实现见 [client.go](../client.go) 和 [internal/redisstore](../internal/redisstore/)。参数、默认值、上限、错误及幂等细则以 [Submit 契约](Submit操作契约.md)为准；实施要求见 [Submit 实施计划](Submit实施计划.md)。

### 2.4 Redis 单次 Claim

- 完成内部包领取入口与嵌入 Lua：从 default 队首原子授予执行权，更新状态、身份、尝试次数及初始租约。写前检查字段、额度、执行身份与相关 key 类型、索引残留；异常候选保留，不自动修复。
- 六字段响应绑定本次调用持有的 owner/token，二进制 payload 无损；区分空队列、一致性异常、非法响应及底层存储或网络错误，保留错误链。仅明确 NOSCRIPT 允许缓存回退，结果未知不重放。

实现与验收见 [claim.go](../internal/redisstore/claim.go)、[claim_task.lua](../internal/redisstore/scripts/claim_task.lua)、[Claim 集成测试](../claim_integration_test.go) 和 [Issue #1](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/1)。调用方须提供禁用自动重试的客户端；NewServer 检查与 Start 接入见第 2.6 节。

### 2.5 单轮本地执行监督

- 内部入口接收明确任务、独立 taskID/token、超时时长和已占用槽，登记后分别启动监督与 Handler；执行超时紧邻 Handler 启动建立，不计入领取和准备时间。
- 监督只裁定一个结果、超时或取消分支；Handler 恢复 panic 并发送一次完整结果，迟到结果不会阻塞退出。已知失权、已生效主动取消或单任务异常禁止新上报，结果、超时和未知 Handler 路径均检查原因。超时先移除续租资格、取消 Handler，再使用独立预算上报失败。
- 结果分支选定后，原执行超时不再改判上报中的业务结果。Handler 实际退出即归还槽，上报管理可继续保留。启动前观察到 abort 时跳过 Handler，由接收路径归还槽并清理。公开退出入口尚待实现。

实现与测试见 [execution.go](../execution.go)、[execution_test.go](../execution_test.go) 和 [Issue #2](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/2)。该入口保持独立可测，现由 Start 的领取循环调用；执行表为空不代表 Handler 已全部退出。

### 2.6 最小 Start 与领取循环

- NewServer 检查禁用自动重试及显式启用 ContextTimeoutEnabled，沿用调用方的 Redis 连接池和配置。Start 封存注册、生成 ownerID 后，非阻塞启动独立的 Claim、Renew 和 Reclaim 循环。Server 对象只能启动一次。配置示例与决策见 [Renew 契约](Renew操作契约.md)、[ADR-0005](adr/0005-renew-client-deadlines.md)。
- 先取得槽，再为每次独立 Claim 生成并持有 token；明确成功后将业务任务与槽交给已有监督。空队列释放槽后等待，暂时性网络错误释放槽后进行可取消且有上限的退避；结果未知不猜测任务、不回滚或透明重放。
- 一致性异常、明确存储错误及非法响应释放本轮领取槽并停止领取。Errors 只通知首个导致停止领取的后台致命错误，后续通知被抑制时仍执行对应的故障处理。无人接收时发送也能完成。公开停止和 Shutdown 仍待实现。

实现与验收见 [start.go](../start.go)、[start_test.go](../start_test.go)、[Start 集成测试](../start_integration_test.go) 和 [Issue #3](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/3)。内部轮询、退避参数以代码常量为准；领取取消与续租生命周期独立，内部循环清理不代表已有公开退出能力。

### 2.7 Server Renew

- 内部存储入口通过嵌入 Lua 原子验证当前状态、token、active 和有效 lease，仅更新目标 score。正常拒绝与数据异常可区分，拒绝和可预见错误不写入；响应丢失不回滚或立即重放。
- 每周期取续租资格快照，锁外串行请求、请求前复查资格，独立截止时间约束真实网络等待；包装与原客户端共享池，保留更短 I/O 超时，不重叠或补跑错过周期。串行容量与网络边界以 [Renew 契约](Renew操作契约.md) 为准。
- 正常拒绝只撤销对应轮次，单任务一致性异常停止领取并维持健康续租。全局续租故障停止 Claim 和 Renew，保留已有执行。此后收到明确成功的迟到 Claim 仍按正常路径接管。

实现与验收见 [renew.go](../renew.go)、[续租存储入口](../internal/redisstore/renew.go)、[续租 Lua](../internal/redisstore/scripts/renew_task.lua) 和 [Issue #8](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/8)。单纯全局续租故障后，已有执行仍可使用独立预算进行真实结果上报。

### 2.8 真实结果上报

- complete 与 ReportFailure 在 Lua 内原子校验执行权、迁移状态、保存结果或错误并清理身份和索引；attempts 保持不变。正常拒绝、一致性错误与结果未知可区分，重复请求保持首次迁移后的结果与时间。
- Server 固定上报内容，使用独立请求预算与有界重试；正常上报保留续租资格，超时上报不恢复资格。每次请求及等待期间响应已知撤销和 abort，最终结束后清理该轮管理。
- 不可恢复上报错误停止新领取，健康任务继续续租和上报；网络耗尽仅结束该轮。使用默认 slog 记录有界诊断，结果未知与业务失败分别处理，正文排除规则及详细预算见契约。
- 独立的 `reportCtx` 承载上报停止状态。显式撤销先停止上报，父取消的可见原因也在调用边界同步传播。Handler 已先因超时取消时，后续仅取消父 context 无法覆盖首个原因，需要显式撤销。

实现与验收见 [report.go](../report.go)、[单次存储入口](../internal/redisstore/report.go)、[Server 集成测试](../report_server_integration_test.go) 和 [Issue #11](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/11)。输入、错误规范化和迁移细则以 [complete 契约](complete操作契约.md)、[ReportFailure 契约](ReportFailure操作契约.md)及 [ADR-0006](adr/0006-result-reporting-lifecycle.md)为准。

Claim、Renew、结果上报与 Reclaim 共用 Redis 网络错误分类。不可重试的 DNS 和地址错误按各操作的致命故障范围处理。分类依据见 [Claim 契约](Claim操作契约.md#存储或网络异常)及 [Issue #13](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/13)。

### 2.9 Server Reclaim

- 两个 Lua 各自原子选取到期候选、整批写前校验并限量迁移。租约到期后按剩余额度进入 retry_wait 或 failed，重试到期后追加到 pending 队尾。只有后续 Claim 会增加 attempts。
- 回收循环独立串行运行，首轮前和每轮结束后随机等待。每个阶段独立使用请求预算，并复用调用方连接池及更短的 I/O 超时。暂时性网络错误结束当前轮，后续轮次重新检查 Redis 当前状态。
- 致命回收错误停止本实例的 Claim 和 Reclaim，保留健康 Renew、Handler 和结果上报。第二阶段校验失败时保留第一阶段已完成的迁移。

实现与边界见 [回收循环](../reclaim.go)、[Reclaim 操作契约](Reclaim操作契约.md)、[ADR-0007](adr/0007-reclaim-batches-and-failure-scope.md)和 [Issue #16](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/16)。

## 5. 当前限制与待确认事项

- **回收推进**依赖至少一个健康回收循环。坏候选会阻塞本批，第一阶段失败会延迟第二阶段。待执行列表未做成员扫描，损坏数据中的 retry/pending 双重成员可能被重复追加。
- **上报容量与执行权**：Handler 退出即可释放槽，上报中的任务数可超过 Handler 并发数；有限预算约束单轮等待，但没有额外上报并发上限。持续网络异常或全局续租停止后，Handler 仍可能在租约到期后产生业务副作用。
- **故障通知**：Errors 只保留首个导致停止领取的后台致命错误，不是全部故障日志，也不表示全服务退出。异常数据不自动修复，故障排除后创建新实例；仅重启进程不保证解决数据问题。
- **串行容量**：renewInterval 的触发周期与租约比例不保证整轮及时完成，任务数量和请求延迟仍可能导致后续任务过期；有界并发留待后续设计。
- **验证范围**：其他 Redis 版本兼容性、统一支持版本范围及 32 位 Go 环境尚未验证；本机测试通过不构成跨版本或部署保证。
- **存储恢复**：Redis 持久化、复制与故障恢复配置尚待明确，未验证持久化恢复或数据丢失窗口。Lua 运行时错误不自动回滚，初版不自动检测、对账或修复部分写入；旧格式试验数据也不自动迁移，见 [ADR-0001](adr/0001-submit-client-and-storage.md)。
- **已保留的执行边界**：取消通知先于本地登记的窗口、Server 本地租约维护及迟到 Claim 响应保护仍未解决，旧 Handler 可能继续产生业务副作用，见 [Claim 契约](Claim操作契约.md)、[Cancel 契约](Cancel操作契约.md)和 [Renew 契约](Renew操作契约.md)。
