# 当前进度

## 1. 当前阶段

Server 本地基础组件、Client Submit、独立的 Redis 单次 Claim 和单轮本地执行监督已实现，尚未串联成完整任务服务。当前优先推进 Server 启动集成，随后为 Renew；边界见第 4 节。

## 2. 已完成的工作

### 2.1 设计与文档

七个核心操作契约、任务字段说明和执行权、租约、重试、取消等机制已建立。设计入口见[项目概览](项目概览.md)，Submit 的接口与存储边界见已接受的 [ADR-0001](adr/0001-submit-client-and-storage.md)；文档已确定不代表对应流程已实现。

### 2.2 Server 本地基础组件

- **构造、注册与启动前检查**：完成配置校验、执行槽和本地表初始化、Handler 注册及启动时封存注册、生成实例身份。构造不请求 Redis 或启动 goroutine；完整启动、运行和停止流程尚未实现。
- **本地执行记录**：业务任务与执行身份分离，按任务 ID 和执行令牌区分轮次；实现带锁的增删查询与快照，取消回调在表锁外调用。
- **结果设置**：完成 JSON 编码、独立缓冲区和大小限制，失败时保留已有结果；尚未接入 Redis 结果上报。

实现与测试见 [server.go](../server.go)、[server_test.go](../server_test.go)。

### 2.3 Client Submit

- 完成提交入口、选项与参数校验，通过嵌入 Lua 原子创建任务详情并入队；同 ID、同初始配置确认已有任务，不同配置返回冲突，缺失配置作为存储异常处理。重复提交不重置运行状态或重新入队。
- 校验脚本响应并保留底层错误链；Redis 连接由调用方配置和关闭，平台不增加 Submit 重试循环或修改共享客户端配置。

实现见 [client.go](../client.go) 和 [internal/redisstore](../internal/redisstore/)。参数、默认值、上限、错误及幂等细则以 [Submit 契约](Submit操作契约.md)为准；实施要求见 [Submit 实施计划](Submit实施计划.md)。

### 2.4 Redis 单次 Claim

- 完成内部包领取入口与嵌入 Lua：从 default 队首原子授予执行权，更新状态、身份、尝试次数及初始租约。写前检查字段、额度、执行身份与相关 key 类型、索引残留；异常候选保留，不自动修复。
- 六字段响应绑定本次调用持有的 owner/token，二进制 payload 无损；区分空队列、一致性异常、非法响应及底层存储或网络错误，保留错误链。仅明确 NOSCRIPT 允许缓存回退，结果未知不重放。

实现与验收见 [claim.go](../internal/redisstore/claim.go)、[claim_task.lua](../internal/redisstore/scripts/claim_task.lua)、[Claim 集成测试](../claim_integration_test.go) 和 [Issue #1](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/1)。调用方须提供禁用自动重试的客户端；NewServer 的重试配置检查、轮询和本地执行接入尚未实现。

### 2.5 单轮本地执行监督

- 内部入口接收明确任务、独立 taskID/token、超时时长和已占用槽，登记后分别启动监督与 Handler；执行超时紧邻 Handler 启动建立，不计入领取和准备时间。
- 监督只裁定一个结果、超时或 abort 分支；Handler 恢复 panic 并发送一次完整结果，迟到结果不会阻塞退出。超时先删除本轮记录并取消再走失败占位，abort 只取消和清理；仍存活的 Handler 保留槽，实际退出才归还。
- complete / reportFailure 为内部、无返回值的空方法，不写 Redis、不提供真实上报成功或重试接口。abort 已预留为关闭 channel 的广播，但生产代码不关闭它，也未提供公开退出入口。

实现与测试见 [execution.go](../execution.go)、[execution_test.go](../execution_test.go) 和 [Issue #2](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/2)。该入口不依赖 Redis Claim，尚待启动集成；执行表为空不代表 Handler 已全部退出。

## 3. 验证摘要

以下为 **2026-11-03 本地执行监督实施阶段**的实际执行记录，环境为 Go 1.26.0、Windows/amd64、go-redis/v9 v9.23.0。本次没有连接 Redis，也未重跑带 integration 标签的测试。

| 已执行命令 | 结果与范围 |
| --- | --- |
| `go test . -run '^TestExecution' -count=1` | 通过成功、业务错误、panic、未知 Handler、超时、abort 广播、迟到结果、轮次隔离及同时触发竞争的定向测试 |
| `go test ./...` | 通过全部单元测试，包含原有 Server、Client 和存储边界测试 |
| `go vet ./...` | 通过 |
| `go test -race ./... -count=1` | 通过全部单元测试，未报告数据竞争 |

本地监督测试使用 channel 和 `testing/synctest` 控制时序，验证忽略取消的 Handler 在监督结束后仍占槽、迟到退出只归还一次，以及旧轮次上报处理中允许新 token 独立存在。上报测试只证明分支调用及清理顺序，不证明真实 Redis 上报成功，见 [execution_test.go](../execution_test.go)。

真实 Redis 验证沿用 **2026-11-02 Claim 实施阶段**的记录：Redis 5.0.14.1 上的 `go test -tags integration -race ./... -count=1` 通过单元及 Submit、Claim 集成测试。Claim 故障测试丢弃第一个成功响应后返回错误，第一个保留 running/active/lease、attempts=1，第二个仍为 pending、attempts=0；另验证异常候选零写入、非法响应不回滚或重放、并发不重复领取、缓存回退、二进制 payload 与数值边界。依据见 [claim_integration_test.go](../claim_integration_test.go)；Submit 的响应丢失与安全重试验证见 [client_integration_test.go](../client_integration_test.go)。这些历史结果不替代本次未执行的 Redis 集成复验。

集成测试需指定 `integration` 标签，Redis 可执行文件由 PATH 或 `TASKQ_REDIS_SERVER` 提供。测试自行启动并清理随机端口、禁用持久化的临时实例，不连接或清空已有部署；本机沙箱内启动 Redis 遇到系统 DLL 重定位错误，已获准在沙箱外完成验证。

## 4. 下一步工作

推进顺序为 **Submit → Claim → Renew**。Submit、单次 Claim 和独立的本地执行监督已完成；Server 启动集成及 Renew 属于后续任务，仍需分别实施与验收。

1. **Server Claim 集成**：按 [Claim 契约](Claim操作契约.md)通过 Start 串联单次 Claim 和已有执行监督，落实执行槽、独立 token 生成、领取轮询和错误分类、NewServer 禁用重试配置检查。无任务或结果未知时释放本轮槽，不为未知任务启动 Handler 或续租；完整生命周期另行实现。
2. **Server Renew**：在 Server Claim 接入并验证后，按 [Renew 契约](Renew操作契约.md)为本地明确管理的执行尝试续租，验证执行权、有效租约、旧令牌拒绝和响应丢失，续租不得重置执行超时。实施仍需单独确认。

真实结果上报、取消与回收等后续流程仍需分别实施和验证。

## 5. 当前限制与待确认事项

- **实现范围**：单次 Claim 与本地执行监督尚未通过 Start 串联；Renew、真实结果上报、取消、回收、查询和完整服务生命周期尚未实现。无续租时长任务可能失权，上报占位不改变 running 状态，lease 到期不会自动迁移；现有测试不代表全流程或自动恢复已验证。
- **验证范围**：其他 Redis 版本兼容性、统一支持版本范围及 32 位 Go 环境尚未验证；本机测试通过不构成跨版本或部署保证。
- **存储恢复**：Redis 持久化、复制与故障恢复配置尚待明确，未验证持久化恢复或数据丢失窗口。Lua 运行时错误不自动回滚，初版不自动检测、对账或修复部分写入；旧格式试验数据也不自动迁移，见 [ADR-0001](adr/0001-submit-client-and-storage.md)。
- **已保留的执行边界**：取消通知先于本地登记的窗口、Server 本地租约维护及迟到 Claim 响应保护仍未解决，旧 Handler 可能继续产生业务副作用，见 [Claim 契约](Claim操作契约.md)、[Cancel 契约](Cancel操作契约.md)和 [Renew 契约](Renew操作契约.md)。
