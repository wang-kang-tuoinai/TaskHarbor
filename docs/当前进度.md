# 当前进度

## 1. 当前阶段

Server 本地基础组件和 Client Submit 已实现并通过相关测试，尚未形成从领取到执行结束的完整任务服务。当前优先推进方向为 Server Claim，随后为 Renew；启动条件见第 4 节。

## 2. 已完成的工作

### 2.1 设计与文档

七个核心操作契约、任务字段说明和执行权、租约、重试、取消等机制已建立。设计入口见[项目概览](项目概览.md)，Submit 的接口与存储边界见已接受的 [ADR-0001](adr/0001-submit-client-and-storage.md)；文档已确定不代表对应流程已实现。

### 2.2 Server 本地基础组件

- **构造、注册与启动前检查**：完成配置校验、执行槽和本地表初始化、Handler 注册及启动时封存注册、生成实例身份。构造不请求 Redis 或启动 goroutine；完整启动、运行和停止流程尚未实现。
- **本地执行记录**：业务任务与执行身份分离，按任务 ID 和执行令牌区分轮次；实现带锁的增删查询与快照，取消回调在表锁外调用。
- **结果设置**：完成 JSON 编码、独立缓冲区和大小限制，失败时保留已有结果；尚未接入 Redis 结果上报。

实现与测试见 [server.go](../server.go)、[server_test.go](../server_test.go)。

### 2.3 Client Submit

- 完成提交入口、选项与参数校验，通过嵌入 Lua 原子创建任务详情并入队；同 ID、同初始配置确认已有任务，不同配置返回冲突，缺失配置作为存储异常处理。重复提交不重置运行状态或重新入队。
- 校验脚本响应并保留底层错误链；Redis 连接由调用方配置和关闭，平台不增加 Submit 重试循环或修改共享客户端配置。

实现见 [client.go](../client.go) 和 [internal/redisstore](../internal/redisstore/)。参数、默认值、上限、错误及幂等细则以 [Submit 契约](Submit操作契约.md)为准；实施要求见 [Submit 实施计划](Submit实施计划.md)。

## 3. 验证摘要

以下沿用 **2026-10-31 Submit 实施阶段**的实际执行记录，环境为 Go 1.26.0、Windows/amd64、本机 Redis 5.0.14.1。本次仅整理文档，未重跑测试。

| 已执行命令 | 结果与范围 |
| --- | --- |
| `go test ./... -run 'Test(NewClient\|Submit\|ParseSubmit)' -count=1` | 通过 Client 参数、选项、默认值、边界、错误链及响应解析的定向单元测试；非法输入不发 Redis 命令 |
| `go test -tags integration ./... -run 'TestSubmitRedis' -count=1 -v` | 通过真实 Redis 定向集成测试，覆盖创建、字段和时间、二进制 payload、幂等与冲突、并发、运行/终态不重置、缺字段优先、错误 key 类型及脚本缓存缺失回退 |
| `go test ./...` | 通过 Server 本地逻辑、Client 和存储响应解析单元测试 |
| `go vet ./...` | 通过 |
| `go test -tags integration -race ./...` | 通过单元及真实 Redis 集成测试，未报告数据竞争 |

集成测试实际丢弃创建响应并断开连接：禁用底层重试时先返回连接错误，调用方以同 ID 重试后确认已有任务；开启底层重试时返回 `Created=false`。两种情况均只入队一次。测试依据见 [client_test.go](../client_test.go)、[submit_test.go](../internal/redisstore/submit_test.go) 和 [client_integration_test.go](../client_integration_test.go)。

集成测试需指定 `integration` 标签，Redis 可执行文件由 PATH 或 `TASKQ_REDIS_SERVER` 提供。测试自行启动并清理随机端口、禁用持久化的临时实例，不连接或清空已有部署；本机沙箱内启动 Redis 遇到系统 DLL 重定位错误，已获准在沙箱外完成验证。

## 4. 下一步工作

推进顺序为 **Submit → Claim → Renew**。Submit 已完成，Claim 与 Renew 的实施仍需用户明确确认。

1. **Server Claim**：按 [Claim 契约](Claim操作契约.md)落实执行槽、原子领取、执行身份与初始租约、尝试计数及本地登记。无任务或结果未知时释放本轮领取占用的槽，不为未知任务启动 Handler 或续租；单独落实禁止不安全透明重试的要求。验证正常领取、空队列、并发竞争和领取响应丢失。
2. **Server Renew**：在 Claim 完成并验证后，按 [Renew 契约](Renew操作契约.md)为本地明确管理的执行尝试续租，验证执行权、有效租约、旧令牌拒绝和响应丢失，续租不得重置执行超时。

Handler 执行、结果上报、取消与回收等后续流程在上述步骤完成后再细化。

## 5. 当前限制与待确认事项

- **实现范围**：Claim、Renew、Handler 执行、超时、结果上报、取消、回收、查询和完整服务生命周期尚未实现；现有测试不代表全流程已经验证。
- **验证范围**：其他 Redis 版本兼容性、统一支持版本范围及 32 位 Go 环境尚未验证；本机测试通过不构成跨版本或部署保证。
- **存储恢复**：Redis 持久化、复制与故障恢复配置尚待明确，未验证持久化恢复或数据丢失窗口。Lua 运行时错误不自动回滚，初版不自动检测、对账或修复部分写入；旧格式试验数据也不自动迁移，见 [ADR-0001](adr/0001-submit-client-and-storage.md)。
- **已保留的执行边界**：取消通知先于本地登记的窗口、Server 本地租约维护及迟到 Claim 响应保护仍未解决，旧 Handler 可能继续产生业务副作用，见 [Claim 契约](Claim操作契约.md)、[Cancel 契约](Cancel操作契约.md)和 [Renew 契约](Renew操作契约.md)。
