**当前阶段：Server 基础组件已实现，下一步开发 Client Submit。**

### 阶段目标

在已确定的七个操作契约基础上，逐步完成任务平台的核心实现，保证代码行为与设计文档一致，并通过测试验证任务状态迁移、执行权校验、租约管理和失败重试等关键机制。

开发过程中优先完成必要的核心功能，再逐步补充边界场景和异常处理，避免在核心流程尚未完成时引入不必要的复杂性。

## 2. 已完成的工作

### 2.1 设计与文档

- 已完成七个核心操作的操作契约：Submit、Claim、Complete、ReportFailure、Renew、Cancel、Reclaim。
- 已确定任务详情记录的主要字段及其分类。
- 已明确任务执行权、租约续期、失败重试、取消和过期回收等关键机制。
- 已整理项目概览，并对操作契约中的部分字段命名和存储规则进行统一。

### 2.2 基础代码实现

根据当前 `server.go` 及 `server_test.go`，已实现以下本地基础能力：

- **Server 构造与配置**：`NewServer` 初始化执行槽、Handler 表和本地执行记录表；提供并发数、租约时长、续租间隔和回收间隔的配置与校验，包括续租间隔不超过租约时长的三分之一。构造时不发起 Redis 请求或启动 goroutine。
- **Handler 注册**：`HandleFunc` 校验空任务类型、空处理函数及重复注册；重复注册保留原 Handler，启动开始后禁止继续注册。
- **启动前置检查**：定义生命周期状态，`beginStart` 要求至少注册一个 Handler，生成 `ownerID` 并将状态从 `serverCreated` 切换为 `serverStarting`；拒绝重复启动。完整启动、运行和停止流程尚未实现。
- **任务与执行身份分离**：`Task` 保存业务视图，`executionKey` 使用 `taskID` 与 `attemptToken` 区分执行尝试，避免删除旧轮次记录时影响新轮次。
- **本地执行记录管理**：实现记录的添加、查询、删除和快照，通过读写锁保护共享表；快照复制表条目，取消回调在表锁之外调用。尚未接入实际任务执行与续租流程。
- **结果设置**：`Task.SetResult` 将结果编码为 JSON，并以独立缓冲区保存，限制编码后大小不超过 1000 字节；编码失败或超限时保留已有结果。

以上为已实现的基础组件，不代表 Claim、Renew 或完整任务执行生命周期已经完成。

## 4. 下一步工作

按 **Client Submit → Server Claim → Server Renew** 的顺序推进，每一步完成实现和相关测试后，再进入下一步。

### 4.1 首先实现 Client Submit

- 在 `client.go` 中实现提交入口，按 Submit 契约完成参数校验和默认值处理。
- 实现首次提交时原子创建任务详情并加入 pending 队列。
- 处理同一 `task_id` 的重复提交：配置一致时返回已有任务，配置不同时返回冲突。
- 验证正常提交、非法参数、重复提交、配置冲突及结果未知后使用相同 ID 重试的行为。

### 4.2 随后实现 Server Claim

- 按 Claim 契约，先取得本地执行槽，再原子领取任务，建立执行身份和初始租约，并增加一次尝试次数。
- 领取成功后登记本地执行尝试；无任务或结果未知时释放本轮执行槽，不为未知任务启动 Handler 或续租。
- 验证正常领取、空队列、并发竞争及领取响应丢失等场景。

### 4.3 再实现 Server Renew

- 对本地明确接收并管理的执行尝试逐任务续租。
- 在同一原子操作中校验状态、执行令牌、索引及租约有效期，并使用 Redis 当前时间更新租约。
- 验证正常续租、旧令牌拒绝、租约到期拒绝及响应丢失；续租不得重置执行超时。

Handler 执行、结果上报、取消、回收等后续流程，待上述步骤完成后再细化，不作为本轮下一步目标。

## 7. 已确认的 Submit 实施决策（2026-10-31）

已形成 [Submit实施计划](Submit实施计划.md) 与 [ADR-0001](adr/0001-submit-client-and-storage.md)。本次仅更新设计文档，Client Submit 和 Redis Lua 尚未实现或验证。

- Client 持有调用方 Redis 客户端，存储层采用内部包函数及嵌入 Lua。
- 输入和存储支持整数毫秒，字段为 execution_timeout_ms、retry_delay_ms；created_at 保留 Unix 毫秒时间戳。
- max_retry 可选、默认 0；Client 与 Server 固定使用 default，queue 保存并参与幂等比较。
- 新建分支写前检查 pending 类型；缺失配置返回 incomplete，区别于冲突。
- payload 上限采用 1 MiB；任务类型格式、长度及其他数值上限和 Redis 支持版本仍待补齐，详见实施计划。
- 已同步相关契约的字段名和时长单位；这不代表已实现代码或完成测试。历史记录中未发现偏差的结论不覆盖这些后续设计变更。
