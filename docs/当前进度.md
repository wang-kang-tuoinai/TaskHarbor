# 当前进度

## 1. 当前阶段

已接通 Submit → Start → Claim → Handler 的最小运行路径，并复用单轮本地执行监督。结果上报仍为空方法，续租、回收与完整退出尚未实现，因此还不是完整任务服务。当前下一步为 Renew；边界见第 4 节。

## 2. 已完成的工作

### 2.1 设计与文档

七个核心操作契约、任务字段说明和执行权、租约、重试、取消等机制已建立。设计入口见[项目概览](项目概览.md)，Submit 的接口与存储边界见已接受的 [ADR-0001](adr/0001-submit-client-and-storage.md)；文档已确定不代表对应流程已实现。

### 2.2 Server 本地基础组件

- **构造、注册与启动前检查**：完成配置校验、执行槽和本地表初始化、Handler 注册及启动时封存注册、生成实例身份。构造不请求 Redis 或启动 goroutine；最小启动接入见第 2.6 节，完整生命周期尚未实现。
- **本地执行记录**：业务任务与执行身份分离，按任务 ID 和执行令牌区分轮次；实现带锁的增删查询与快照，取消回调在表锁外调用。
- **结果设置**：完成 JSON 编码、独立缓冲区和大小限制，失败时保留已有结果；尚未接入 Redis 结果上报。

实现与测试见 [server.go](../server.go)、[server_test.go](../server_test.go)。

### 2.3 Client Submit

- 完成提交入口、选项与参数校验，通过嵌入 Lua 原子创建任务详情并入队；同 ID、同初始配置确认已有任务，不同配置返回冲突，缺失配置作为存储异常处理。重复提交不重置运行状态或重新入队。
- 校验脚本响应并保留底层错误链；Redis 连接由调用方配置和关闭，平台不增加 Submit 重试循环或修改共享客户端配置。

实现见 [client.go](../client.go) 和 [internal/redisstore](../internal/redisstore/)。参数、默认值、上限、错误及幂等细则以 [Submit 契约](Submit操作契约.md)为准；实施要求见 [Submit 实施计划](Submit实施计划.md)。

### 2.4 Redis 单次 Claim

- 完成内部包领取入口与嵌入 Lua：从 default 队首原子授予执行权，更新状态、身份、尝试次数及初始租约。写前检查字段、额度、执行身份与相关 key 类型、索引残留；异常候选保留，不自动修复。
- 六字段响应绑定本次调用持有的 owner/token，二进制 payload 无损；区分空队列、一致性异常、非法响应及底层存储或网络错误，保留错误链。仅明确 NOSCRIPT 允许缓存回退，结果未知不重放。

实现与验收见 [claim.go](../internal/redisstore/claim.go)、[claim_task.lua](../internal/redisstore/scripts/claim_task.lua)、[Claim 集成测试](../claim_integration_test.go) 和 [Issue #1](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/1)。调用方须提供禁用自动重试的客户端；NewServer 检查与 Start 接入见第 2.6 节。

### 2.5 单轮本地执行监督

- 内部入口接收明确任务、独立 taskID/token、超时时长和已占用槽，登记后分别启动监督与 Handler；执行超时紧邻 Handler 启动建立，不计入领取和准备时间。
- 监督只裁定一个结果、超时或 abort 分支；Handler 恢复 panic 并发送一次完整结果，迟到结果不会阻塞退出。超时先删除本轮记录并取消再走失败占位，abort 只取消和清理；仍存活的 Handler 保留槽，实际退出才归还。
- complete / reportFailure 为内部、无返回值的空方法，不写 Redis、不提供真实上报成功或重试接口。abort 已预留为关闭 channel 的广播，但生产代码不关闭它，也未提供公开退出入口。

实现与测试见 [execution.go](../execution.go)、[execution_test.go](../execution_test.go) 和 [Issue #2](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/2)。该入口保持独立可测，现由 Start 的领取循环调用；执行表为空不代表 Handler 已全部退出。

### 2.6 最小 Start 与领取循环

- NewServer 拒绝开启自动重试的客户端，不修改共享配置、不新建连接池。Start 封存注册、生成 ownerID 后非阻塞启动领取循环；已有对象不能重复启动或重启。
- 先取得槽，再为每次独立 Claim 生成并持有 token；明确成功后将业务任务与槽交给已有监督。空队列释放槽后等待，暂时性网络错误释放槽后进行可取消且有上限的退避；结果未知不猜测任务、不回滚或透明重放。
- 一致性异常、明确存储错误及非法响应释放槽并停止领取，通过容量为 1 的 Errors 通知调用方；无人接收不阻塞停止，已有 Handler 和监督继续执行。生产路径不主动关闭 abort，也未新增公开停止或 Shutdown 接口。

实现与验收见 [start.go](../start.go)、[start_test.go](../start_test.go)、[Start 集成测试](../start_integration_test.go) 和 [Issue #3](https://github.com/wang-kang-tuoinai/TaskHarbor/issues/3)。内部轮询、退避参数以代码常量为准；领取循环的内部取消仅用于当前测试收尾，不代表已有公开退出能力。

| `go test -tags integration . -run '^TestStartRedis' -count=1 -v` | 通过真实 Redis 的 Submit→Start→Claim→Handler、并发槽上限及真实领取响应丢失测试 |

| `go vet ./...` | 通过 |
| `go test -tags integration -race ./... -count=1` | 修复新增测试观测的共享切片竞争后复验通过，未再报告数据竞争；覆盖全部单元与真实 Redis 集成测试 |

Start 单元测试使用 channel 和 `testing/synctest` 控制时序，验证无槽不请求、空队列和网络故障不产生致命通知、退避有上限且可取消，以及领取停止不取消已有执行。已有监督测试继续验证迟到结果、真实退出才归还槽和 token 隔离，见 [start_test.go](../start_test.go)、[execution_test.go](../execution_test.go)。

真实 Redis 测试验证五个任务受并发槽上限约束，Handler 返回后任务仍为 running，空上报不写结果或终态。故障测试丢弃第一个 Claim 成功响应，在新 token 生成处暂停后续独立领取，确认第一个保留 running/active/lease、attempts=1，第二个仍为 pending、attempts=0，未执行或登记未知任务；放行后仅第二个以新 token 执行。测试完成后清理领取循环与本地执行，见 [start_integration_test.go](../start_integration_test.go)。既有 Submit 安全重试和 Claim 原子性、非法响应、并发与响应丢失测试也在最终集成回归中通过，见 [client_integration_test.go](../client_integration_test.go)、[claim_integration_test.go](../claim_integration_test.go)。

集成测试需指定 `integration` 标签，Redis 可执行文件由 PATH 或 `TASKQ_REDIS_SERVER` 提供。测试自行启动并清理随机端口、禁用持久化的临时实例，不连接或清空已有部署；本机沙箱内启动 Redis 遇到系统 DLL 重定位错误，已获准在沙箱外完成验证。

## 4. 下一步工作

推进顺序为 **Submit → Claim → Renew**。Submit、Claim 与本地执行监督已通过最小 Start 串联；Renew 属于下一阶段，仍需单独实施与验收。

**Server Renew**：按 [Renew 契约](Renew操作契约.md)为本地明确管理的执行尝试续租，验证执行权、有效租约、旧令牌拒绝和响应丢失，续租不得重置执行超时。实施仍需单独确认。

真实结果上报、取消与回收等后续流程仍需分别实施和验证。

## 5. 当前限制与待确认事项

- **实现范围**：Renew、真实结果上报、取消、回收、查询和完整服务生命周期（公开停止、Shutdown 与排空）尚未实现。无续租时长任务可能失权，上报占位不改变 running 状态，lease 到期不会自动迁移；现有测试不代表全流程或自动恢复已验证。
- **领取停止**：Errors 仅报告致命领取错误，不表示已有执行或全服务已退出。异常队首不自动丢弃或修复，需人工修复并创建新实例；仅重启进程不保证解决数据问题。
- **验证范围**：其他 Redis 版本兼容性、统一支持版本范围及 32 位 Go 环境尚未验证；本机测试通过不构成跨版本或部署保证。
- **存储恢复**：Redis 持久化、复制与故障恢复配置尚待明确，未验证持久化恢复或数据丢失窗口。Lua 运行时错误不自动回滚，初版不自动检测、对账或修复部分写入；旧格式试验数据也不自动迁移，见 [ADR-0001](adr/0001-submit-client-and-storage.md)。
- **已保留的执行边界**：取消通知先于本地登记的窗口、Server 本地租约维护及迟到 Claim 响应保护仍未解决，旧 Handler 可能继续产生业务副作用，见 [Claim 契约](Claim操作契约.md)、[Cancel 契约](Cancel操作契约.md)和 [Renew 契约](Renew操作契约.md)。
