# 领域文档使用规则

## 阅读入口

- 了解架构与范围时，阅读 `docs/项目概览.md`。
- 确认实现进度时，阅读 `docs/当前进度.md`，并核对相关代码和测试。
- 处理具体操作时，阅读对应的 `docs/*操作契约.md`；涉及存储字段时，同时阅读 `docs/任务详情记录相关字段.md`。
- 涉及设计决策时，先阅读 `docs/adr/README.md`，再阅读与当前任务相关的 ADR。
- 根目录 `GLOSSARY.md` 存在时，使用其中定义的术语；不存在时沿用相关契约与 ADR 的用词，继续工作。仅在实际需要澄清领域术语时建立词汇表。

以上路径均相对于仓库根目录。

## ADR 约定

沿用 `docs/adr/README.md` 的编号、状态及替代规则。

- ADR 保存在 `docs/adr/`，文件名沿用四位编号加英文短名。
- 新建前检查现有编号，顺序递增，不覆盖或重编号已有记录。
- 状态使用“提议”“已接受”“已废弃”“已替代”。
- 改变已接受决策时，新增 ADR 并注明替代关系，同步维护原 ADR 的状态和索引，保留历史决策内容。
- 结构沿用现有 ADR：状态、日期、背景、决策、后果、替代方案及关联。
- 只有实际讨论形成的决策才写入 ADR；初始化配置不创建示例 ADR。

## 文档与实现的关系

操作契约、字段说明和已接受 ADR 共同约束实现。任务描述与实施计划引用这些依据，不自行改变既定行为。

发现文档之间或文档与实现冲突时，说明冲突位置、触发条件和影响，按 `agents.md` 的规则确认处理方案。

ADR 被接受不代表代码已经实现；完成状态以实际代码和已执行的测试为依据。
