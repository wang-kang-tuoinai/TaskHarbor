# ADR-0006：结果上报的生命周期与故障范围

- 状态：已接受
- 日期：2026-11-07
- 关系：补充 ADR-0003、ADR-0004、ADR-0005；将既有首个后台致命错误通知机制应用于结果上报，不改变 Claim/Renew 的故障处理。

## 背景

真实上报替换占位后，监督流程会等待网络与重试。Handler 执行结束、租约有效、结果被 Redis 接受是不同事件：复用已经超时取消的 Handler context 会使超时失败无法上报；继续监听原执行超时可能把已选定的成功结果改判为失败。上报故障也不能解释成业务执行失败。

## 决策

1. 内部存储操作只执行一次并返回 applied、error；Server 管理固定参数、有界请求与重试、取消检查、日志和致命错误；监督选择唯一结果分支并最终清理。不新增公开上报 API，不引入通用重试框架。
2. 上报使用独立请求预算，不直接继承 Handler 因执行超时取消的 context，不绑定 Claim/Renew 循环。每次请求前和等待期间响应已知失权、已生效取消、一致性撤销及 abort；不能仅靠进入上报前的检查。在途请求仍由 Redis 执行权校验，不承诺撤回已生效操作。
3. 结果分支选定后，执行超时不再改变成功或失败结果，上报受独立预算约束；超时分支选定后，不接受迟到结果。两者同时就绪沿用既有单分支裁定。
4. 正常结果上报期间保留续租资格，Renew 正常时继续续租；超时上报前移除资格且不恢复。Handler 实际退出即释放槽，无需等上报结束；监督最终清理记录。因此上报中的任务数可以超过 Handler 并发数，本轮不另设上报并发限制。
5. 参数、一致性、明确权限或脚本错误及非法响应结束该轮上报与续租，调用 reportFatal 停止新领取；其他任务继续续租和上报。正常拒绝不触发致命通知；暂时性网络错误重试耗尽只结束该轮，不仅凭此停止领取。complete 故障不能转为 ReportFailure。
6. 标准库 slog 记录诊断，Errors 仍只通知实例首个致命错误，后续通知被抑制仍执行故障处理。不新增日志依赖、公开 logger 配置或另一条错误 channel。存储结果未知不能记成业务执行失败。

## 后果与限制

- 保留网络波动后上报的机会，但请求预算不保证赶在租约内完成。响应丢失后拒绝也不能证明第一次没有成功，不自动查询或安排业务重试来补偿。
- Handler 槽限制不等于上报并发限制；有限请求预算限制单轮存活时间，但不构成上报总数量的固定上限。
- Redis 执行权校验不能撤销业务副作用。本轮不实现本地租约保护、Reclaim、Cancel 或 Shutdown；retry_wait 不会自动重新入队，遗留 running 不承诺自动回收。
- 本决策是实施依据，不表示空方法已替换或测试已通过。预算数值、日志级别与格式限制见操作契约。

## 替代方案

- 复用 Handler context：不采用，超时失败路径已取消它。
- 将执行超时延伸到结果提交：不采用，会使业务结果因上报耗时而被重新裁定。
- 上报结束才释放 Handler 槽：不采用，改变已有资源归属并将业务并发与存储等待混合。
- 存储层和 Server 都重试：不采用，可能使三次预算相乘。
- 上报异常停止所有续租或把 complete 失败改为业务失败：不采用，扩大影响或篡改业务结果。
