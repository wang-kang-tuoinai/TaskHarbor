# ADR-0010：Cancel 通知的 Unicode 边界

- 状态：已接受
- 日期：2026-11-19
- 关系：部分替代 ADR-0009 第 2 点的通知编码条件，明确第 4 点的无效消息处理。

## 背景

Submit 接受任意非空任务 ID 字节，Redis 按原始字节保存。Go 的 JSON 解码会将非法 UTF-8 字节或未配对的 UTF-16 代理项转义替换为 U+FFFD。替换后的通知可能命中另一个任务的执行身份。

## 决策

1. Cancel 使用原始任务 ID 定位和取消任务。原 running 任务的 ID 含非法 UTF-8 时跳过 JSON 通知，保留权威取消成功，使用现有诊断路径记录原因。
2. 消费者丢弃含非法 UTF-8 或未配对 UTF-16 代理项转义的 JSON 消息，记录诊断并继续消费。有效代理项对按其 Unicode 字符解析，合法的 U+FFFD 参与执行身份精确匹配。

## 后果

- 非法 UTF-8 ID 的任务仍可取消，其执行身份由 Redis 撤销，Worker 可能无法立即收到本地取消信号。
- 发布和接收均保留执行身份的精确匹配语义。

## 替代方案

- 拒绝取消含非法 UTF-8 的任务会让已提交的任务无法通过 Cancel 撤销执行权。
- 接受 JSON 解码的替换行为可能撤销错误的本地执行。
