# ADR-0002：Claim 的重试边界与异常处理

- 状态：已接受
- 日期：2026-11-02
- 关系：补充 ADR-0001 的 Claim 重试要求，不替代其 Submit 决策。

## 背景

普通 Claim 不具备请求幂等性。Redis 可能已授予一个任务的执行权，而调用方没有收到响应；透明重试可能领取另一个任务。另一方面，异常队首若不移除会持续阻塞领取，但自动丢弃或隔离任务又需要新的恢复规则。

## 决策

1. Server 使用调用方提供且禁用自动重试的 Redis 客户端。调用方构造客户端时设置 MaxRetries=-1；NewServer 检查初始化后的有效配置（当前 go-redis 中为 0），拒绝开启重试的配置。不修改共享客户端，也不内部创建连接池。Submit 如需不同重试策略，由调用方提供另一个客户端。
2. 仅在明确收到 NOSCRIPT、确认该次脚本未执行时允许脚本缓存回退。Claim 结果未知时不重放原请求、不猜测任务身份、不启动 Handler、不登记续租，并释放本轮执行槽。之后的轮询是新的独立领取，不用于找回原结果。
3. 空队列是正常结果，释放槽后等待下一轮。暂时性网络故障释放槽，进行可取消且等待时长有上限的退避。具体间隔属于实施参数，尚未固定。
4. 明确的候选数据一致性异常不丢弃队首、不自动修复；停止该实例的领取循环，报告包含任务身份的错误。已有任务继续执行和处理结果。不能把权限、脚本或 WRONGTYPE 等明确错误一概当成网络故障重试。
5. 成功领取后找不到 Handler，按本轮执行失败处理，交给 ReportFailure 路径。共享 default 队列的 Server 应具备处理队列中全部任务类型的能力；第一版不实现按 Handler 类型筛选领取。

## 后果与限制

### 2026-11-02 补充确认

补齐上述第 4 项此前未明确的错误处理：权限错误、脚本错误、错误 key 类型等明确的非暂时性错误，以及非法响应，均释放本轮槽、停止领取并通过 Errors 报告，已有任务继续处理。非法响应可能对应已生效的 Claim，不执行未知任务、不回滚状态或尝试次数。明确 NOSCRIPT 仍允许缓存回退；暂时性网络故障仍按原决策退避。本补充不改变既有重试边界。

### 已知限制

- 响应丢失的任务可能仍为 running，并消耗一次尝试。恢复依赖租约回收；在 Reclaim 尚未实现的阶段，不承诺自动恢复。
- 异常队首会阻塞其后的正常任务；其他 Server 也可能遇到同一异常并停止领取。需要人工修复，并重新创建、启动实例；仅重启进程未必解决问题。
- 未注册 Handler 会消耗尝试预算，不会自动退回 pending。结果上报仍为占位时，这条路径不产生 Redis 失败迁移。
- 依赖升级时需要复核客户端重试配置的语义，并用真实响应丢失测试证明不会领取第二个任务。

## 替代方案

- 开启透明重试：拒绝，会在一次本地领取中授予多个任务执行权。
- 单命令禁重试包装：可行，但当前选择显式客户端前置条件，减少专用执行包装。
- 自动移除或隔离异常队首：暂不采用，需要额外定义数据归属和恢复流程。
- 遇到一致性异常立即循环：拒绝，会反复命中同一记录并形成请求与日志洪泛。

## 实现与文档状态

这是已接受的设计，不表示已实现。现有 NewServer 尚未检查重试配置，Claim 尚未实现。后续实施应将本决策同步至 Claim 契约的错误处理与实例配置说明；不将本 ADR 当作测试通过的证据。
