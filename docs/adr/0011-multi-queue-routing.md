# ADR-0011：多队列路由、调度和故障范围

- 状态：已接受，待实施
- 日期：2026-11-27
- 关系：部分替代 ADR-0001 的固定 default 限制；扩展 ADR-0002、0007、0009 的多队列行为。

## 背景

任务 ID 已能独立定位详情。开放多个队列后，取消、回收和上报必须一致地选择索引，同时保持已有 default 数据可读可消费。

## 决策

1. 一个 ID 全平台对应一个任务，queue 是首次提交确定的不可变配置。索引沿用 taskq:<queue>:<索引名>；详情沿用 taskq:meta:<task_id>。队列名为 1–64 个 ASCII 字母、数字、下划线或连字符，区分大小写。禁用 meta，避免其 pending 索引与 ID 为 pending 的任务详情碰撞。
2. Submit 省略队列取 default。Cancel 在同一脚本读取权威队列并操作索引；GetTask 只检查 Hash 中名称是否合法。支持单个可写主节点的数据集，可以有副本；跨槽原子迁移不在本轮范围。
3. Server 在构造时确定消费列表，全部队列共享本地并发额度；各实例须注册其消费队列可能领取到的全部任务类型。Claim 逐队列轮转，只有明确为空才立即探测下一队列。每次请求独立生成 token。本地执行记录携带队列；每次续租和上报在当前尝试身份匹配后核对队列再操作索引。
4. Reclaim 单循环串行处理配置队列，阶段限批。暂时性错误仅跳过本队列本轮剩余阶段；致命回收错误停本实例全部领取和回收。Claim 自身致命错误只停领取。取消通知仍按 owner 发布。

## 替代方案

要求 Cancel 调用方重复提供 queue 会引入 ID 与队列不匹配的输入。随机探测可能连续跳过有积压的队列；轮转让持续有工作的队列依次获得机会。每队列独立回收协程可降低慢队列对其他队列的影响，但并发请求数会随配置队列数增长。

## 后果与升级

整轮全空时最多探测配置队列数次。串行回收时慢队列会推迟后续队列；无在线实例负责的队列暂不回收或调度重试。单个坏队列可能使混合消费实例停止领取。轮转只约束每实例的领取机会，不保证各队列完成数量相同。

现有 default 任务无需迁移。先升级消费目标队列的 Server 及可能查询、取消相关任务的 Client，再启用自定义队列提交。旧版读取自定义队列可能报告一致性错误。
