# ADR-0004：续租资格与续租故障的影响范围

- 状态：已接受
- 日期：2026-11-04
- 关系：部分替代 ADR-0003 的执行表语义及 Errors 通知定义；其余资源归属、执行监督与退出决策继续有效。补充 ADR-0002，不改变 Claim 重试边界。

## 背景

Renew 无法继续工作，不意味着所有原租约已经失效。立即取消所有 Handler 会放弃仍可能被接受的结果；停止续租时清空执行表，又迫使在途 Claim 的迟到成功响应走特殊接管路径。另一方面，单任务损坏不应停止其他健康任务续租，正常失权也不应当成实例故障。

原 Errors 通知依赖只有 Claim 一个发送者、最多发送一次。接入 Renew 后，两个模块可能同时报告，直接发送会破坏无人读取时不阻塞的保证。

## 决策

1. executions 表保存本地具备续租资格的执行尝试，不证明租约有效，也不保证实际续租。是否发起续租由 Renew 模块运行状态决定；表的存在性不能作为允许上报的依据。
2. 正常续租拒绝只取消并移除对应轮次，不停止领取或其他任务续租，也不进入 Errors。
3. 单任务一致性异常取消并移除对应轮次，不伪造业务失败上报；停止新领取并报告带身份的错误，其他健康任务继续执行、续租和处理结果。不自动修复或隔离 Redis 数据。
4. 权限、脚本等全局致命续租故障以及非法响应，停止新领取和 Renew，报告错误；不清空执行表，不仅因该故障取消 Handler。已有监督继续按结果、超时或其他明确取消原因处理并清理记录。在途 Claim 明确成功后沿用正常接管流程，不引入无续租专用分支。非法响应可能对应已生效请求，不回滚租约。
5. 暂时性网络故障或响应丢失不立即重试，不据此取消 Handler；继续扫描其他任务，下一轮重新校验。全局续租故障不恢复该实例的循环，修复后创建新实例。
6. 监督用明确取消原因区分失权、已生效的主动取消、本地超时和 abort。已知失权、主动取消或单任务一致性异常后，不再发起结果上报；不能只增加取消 select 分支而忽略结果分支的竞争。检查后才到达的取消与已在途上报仍由 Redis 校验执行权，不引入消除该窗口的复杂串行化。超时仍按失败流程处理，abort 不伪造失败。
7. Errors 为容量 1 的只读 channel，供一个调用方接收实例首个导致停止领取的后台致命错误，来源可为 Claim 或 Renew；后续错误不再发送，没人读取也不得阻塞任何故障处理。即使后续通知被抑制，相应故障处理仍须执行。不关闭 channel 来暗示服务结束；收到错误不代表所有 Handler 或后台协程已退出。

## 后果与限制

- 保留尚在有效租约内完成并上报的机会，同时接受续租停止后 Handler 在租约到期后仍可能执行并产生副作用。第一版没有本地租约截止保护；平台状态校验不能撤回业务副作用。
- 续租循环与 Claim 取消生命周期独立：Claim 停止不应连带停止健康任务续租。
- 保留正常登记、监督与清理路径，避免清空执行表和迟到 Claim 的额外竞争；表为空仍不能证明所有 Handler 已退出。
- 移除记录或停止循环不能撤回已在途 Renew，它仍可能延后回收。取消或监督结束不提前释放仍存活 Handler 的槽。
- Errors 只通知首个致命错误，调用方不能依靠它获得全部故障明细。
- 当前真实结果上报仍是占位；本 ADR 不表示 Renew 或真实成功上报已经实现。串行扫描的容量限制和验收边界见 Renew 契约。

## 替代方案

- 全局 Renew 故障立即取消所有 Handler：不采用；可能仍有有效租约和即将完成的任务，故障本身不是明确失权。
- 停止 Renew 时清空执行表：不采用；混淆资格与服务运行状态，并增加迟到 Claim 的特殊接管和同步需求。
- 单任务损坏停止所有续租：不采用；扩大故障影响，健康任务也会失去续租机会。
- 所有 Renew 错误都等待下一轮：不采用；掩盖明确的配置、脚本和数据异常。
- 多个模块直接发送容量 1 的错误 channel：不采用；无人读取时可能阻塞第二个发送者。
