# 任务详情记录相关字段

第一版任务详情使用 Redis Hash 保存，共 17 个字段。不可变配置在首次 Submit 时确定，后续操作不得覆盖；重复提交时比较 task_type、payload、max_retry、execution_timeout_ms、queue、retry_delay_ms，task_id 用于定位同一任务。

| 分类 | 字段 | 作用与约定 |
| --- | --- | --- |
| 不可变配置 | `task_id` | 任务唯一标识，用于查询、取消、索引关联和重复提交识别。同一次逻辑提交重试复用同一 ID。 |
| 不可变配置 | `task_type` | 任务类型，Server 根据该值查找已注册的 handler。 |
| 不可变配置 | `payload` | 传递给 handler 的业务参数。重复提交按最初序列化的字节内容比较，无参数时使用统一空值约定。 |
| 不可变配置 | `max_retry` | 首次尝试之外允许重试的最大次数，非负整数，提交时省略默认 0。最大尝试次数为 max_retry + 1；0 表示不重试。 |
| 不可变配置 | `execution_timeout_ms` | 单次执行的本地超时时长，单位为整数毫秒，默认 60 秒且必须大于 0。Server 启动 handler 时同时开启完整时长的定时器，不计入 Claim 耗时；续租不重置计时。 |
| 不可变配置 | `queue` | 任务所属的逻辑队列，用于定位 pending、active、lease、retry 等索引。第一版固定保存 default，Client 与 Server 均只使用此队列，不开放选择；参与幂等比较。 |
| 不可变配置 | `retry_delay_ms` | 每次进入 retry_wait 后的等待时长，单位为整数毫秒，默认 30 秒且不得小于 15 秒。ReportFailure、Reclaim 读取该值，以 Redis 当前时间加上 retry_delay_ms 生成重试到期时间。 |
| 运行状态 | `status` | 任务当前状态：pending、running、retry_wait、completed、failed、canceled。首次提交为 pending，后三种为终态。 |
| 运行状态 | `attempts` | 已授予执行权的尝试次数，初始为 0。每次 Claim 成功恰好增加 1；即使 handler 未启动也消耗该次额度。失败上报、回收和重新入 pending 不增加或退回次数。 |
| 当前执行权 | `owner_id` | 当前领取任务的 Server 实例标识，实例启动时生成，重启后更换。Claim 时写入，退出 running 时清除。 |
| 当前执行权 | `attempt_token` | 本轮执行尝试的唯一身份。每轮 Claim 使用新值，续租和结果上报必须匹配，防止旧 Worker 修改新一轮任务；退出 running 时清除。 |
| 结果与诊断 | `result` | handler 成功返回后由 complete 保存的业务结果，可以为空。提交结果必须通过当前状态、token 和有效租约校验。 |
| 结果与诊断 | `last_error` | 最近一次被平台接受的失败或租约到期原因，由 ReportFailure、Reclaim 更新。可保留到后续成功；非 running 任务不接受补报错误。 |
| 结果与诊断 | `created_at` | 任务首次创建时间，重复 Submit 不修改。 |
| 结果与诊断 | `last_claimed_at` | 最近一次 Claim 成功授予执行权的时间，每轮领取更新。用于诊断，不作为本地 execution_timeout_ms 的计时起点。 |
| 结果与诊断 | `last_failed_at` | 最近一次失败上报或租约回收被平台接受的时间，与 last_error 同步更新。 |
| 结果与诊断 | `finished_at` | 任务进入 completed、failed 或 canceled 的时间。非终态不设置，重复终态请求不刷新。 |

时间戳统一使用 Redis 当前时间生成的 Unix 毫秒；execution_timeout_ms、retry_delay_ms 使用整数毫秒，计算索引时间及转换为内部时长时须检查溢出。

score 不是任务详情 Hash 的字段：lease ZSET 以 task_id 为 member、租约到期时间为 score；retry ZSET 以 task_id 为 member、允许重新进入 pending 的时间 next_retry_at 为 score。next_retry_at 仅是该 score 的语义名称，不作为字段单独存储在任务详情 Hash 中。两种到期时间分别保存在对应 ZSET 中，不在任务详情重复保存。
